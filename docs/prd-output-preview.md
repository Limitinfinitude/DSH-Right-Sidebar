# Output Dock 产物预览 PRD

## 1. 背景与问题

Output Dock 的职责不是复刻资源管理器，也不是展示 Agent 写出的每一个文件。它应当集中呈现当前会话里用户可以直接阅读、检查、下载或使用的产物。

当前实现并非只显示 Markdown 与 SVG：图片、PDF 以及 `txt/json/csv/yaml` 等文本也会显示；但它们目前被归为同一种 `text` 预览。`html/htm` 与所有源码文件则会被主动排除。这个规则虽然避免了前后端项目产生大量文件时淹没侧栏，但还缺少“哪些文件值得作为产物、应当如何预览”的产品边界。

## 2. 产品目标

1. 侧栏默认只收集对最终用户有直接价值的产物，不展示项目源码、构建中间文件、依赖和配置噪声。
2. 一个产物有合适的展示方式时，优先展示内容而不是文件名或原始文本。
3. 不支持预览的文件不进入默认标签栏；用户仍可通过 DSH 工作区访问它们。
4. 新增预览能力不能显著增加侧栏空闲状态的 CPU、内存或初始网络负担。
5. 会话切换时，产物、关闭状态、标签排序与预览状态随会话切换。

## 3. 核心原则

### 3.1 以“用户消费”而不是扩展名为准

同为 HTML，项目中的 `src/App.html` 是源码，不应出现在 Dock；Agent 部署后给出的 `http://localhost:xxxx` 是可运行成果，应当作为“运行链接”出现在对话和可选的预览入口中。Dock 不自动把 HTML 源文件当作网页成果。

同为 JSON，`package.json` 是项目配置，不应出现；`report.json`、API 导出、分析结果等由 Agent 明确生成给用户的数据可以出现。

### 3.2 默认克制，按需展开

默认标签栏只放可直接预览的用户产物。复杂或潜在昂贵的渲染只在用户选中该标签后初始化；不对所有文件预读、解析或做质量检查。

### 3.3 产物与源码分流

DSH 对话负责说明 Agent 做了什么，工作区负责代码与项目文件，Output Dock 负责可交付结果。三者互相链接，但不重复承担对方职责。

## 4. 文件支持矩阵

| 优先级 | 文件类型与扩展名 | Dock 默认行为 | 预览形式 | 编辑策略 |
| --- | --- | --- | --- | --- |
| P0 | Markdown: `md`, `mdx` | 收集 | 安全渲染的富文本、图片和表格 | 直接在渲染内容上编辑，静默保存 |
| P0 | SVG: `svg` | 收集 | 自适应画布，保留比例并重写本地资源引用 | 暂不编辑 |
| P0 | 图片: `png`, `jpg`, `jpeg`, `webp`, `gif`, `avif`, `bmp` | 收集 | 自适应图片预览 | 只读，下载或在工作区打开 |
| P0 | PDF: `pdf` | 收集 | 浏览器 PDF 预览 | 只读，下载或在工作区打开 |
| P0 | 纯文本文档: `txt`, `log` | 收集 | 文本阅读器，限制超大文件初始载入 | 可编辑，静默保存 |
| P1 | 表格数据: `csv`, `tsv` | 收集 | 表格视图，首行作为表头；可切换原始文本 | 后续支持单元格编辑，第一期只读 |
| P1 | 结构化数据: `json`, `jsonl`, `yaml`, `yml`, `toml`, `xml` | 仅当为显式产物时收集 | 可折叠树形/格式化阅读器；提供原始文本切换 | 后续支持结构化编辑；第一期原始文本编辑 |
| P1 | 文档: `docx`, `xlsx`, `pptx`, `ods`, `odt` | 不自动收集，Agent 明确标记为产物时收集 | 首期显示文件信息、下载和“在工作区打开”；后续接入轻量只读渲染 | 不在 Dock 编辑 |
| P1 | 媒体: `mp3`, `wav`, `ogg`, `mp4`, `webm` | Agent 明确标记为产物时收集 | 浏览器原生音频/视频播放器 | 只读 |
| P2 | 图表与图形描述: `mermaid`, `mmd`, `dot`, `graphml` | Agent 明确标记为产物时收集 | 受限、按需加载的渲染器；失败时显示原文本和下载 | 不在 Dock 编辑 |
| P2 | 压缩包: `zip`, `tar`, `gz`, `7z` | 不进入标签栏 | 文件摘要、下载、工作区打开 | 不编辑 |
| 永不默认收集 | 源码: `js`, `ts`, `tsx`, `py`, `css`, `vue`, `sql` 等 | 不收集 | 由工作区代码浏览器处理 | 不在 Dock 编辑 |
| 永不默认收集 | 项目配置与依赖: `package.json`, lock 文件、`.env`、`tsconfig`、`vite.config`、`node_modules` 等 | 不收集 | 由工作区处理 | 不在 Dock 编辑 |
| 特殊规则 | `html`, `htm` | 不按文件收集 | 运行 URL 或部署 URL 才能作为网页成果预览 | 不编辑 HTML 源码 |

## 5. 产物判定规则

### 5.1 自动收集

以下文件在 Agent 新建或更新时自动进入 Dock：P0 文件类型，以及 P1 的 CSV/TSV。它们通常就是用户请求的报告、图片、图表、文档或数据导出。

### 5.2 需要 Agent 显式标记

结构化数据、Office 文件、媒体、图形描述和压缩包容易同时充当项目内部文件。它们只有在 Agent 的工具结果标记为用户产物，或在对话中以“已生成：文件路径”明确发布时，才加入 Dock。

### 5.3 永久排除

源码、项目配置、依赖、缓存、构建目录与隐藏凭据文件不进入 Dock，也不出现在“本会话产物”目录中。文件名命中下列语义时同样排除：`package.json`、锁文件、`.env*`、`tsconfig*.json`、构建配置、`dist/`、`build/`、`node_modules/`、`.git/`。

### 5.4 网页成果

若 Agent 启动或部署了服务，应向对话发布可点击 URL。Dock 可以在后续版本加入“运行中的网页”条目：显示 URL、刷新、在浏览器打开与停止服务，但不收集其 HTML/JS/CSS 源文件。一个会话允许存在多个 URL，并按端口、项目根目录和会话 ID 隔离。

## 6. 交互与布局

1. 新产物产生后自动打开已收起的右侧栏，并选择新产物；源码更新不触发打开。
2. 顶部为可关闭、可拖动重排的堆叠标签。关闭仅影响当前会话的可见标签，不删除文件。
3. 底部“本会话产物”目录可重新打开已关闭标签，且仅列出符合本 PRD 的用户产物。
4. 预览区域根据类型使用专用阅读器；无法解析时显示轻量错误状态、文件名、下载和工作区入口，不展示空白面板。
5. 所有预览保留下载、复制路径、在资源管理器中显示；只有安全的文本类产物提供编辑。
6. 窄侧栏下优先保持内容可见：图片/SVG 等比例缩放，表格横向滚动仅限表格容器，文本自动换行且可切换不换行模式。

## 7. 性能与安全要求

1. Dock 关闭或未选中产物时不得读取文件内容、解析文档、初始化 iframe 或启动预览器。
2. 大文件采用大小阈值：文本超过 1 MB 显示前 256 KB 与下载入口；表格超过 10,000 行只渲染可视区域；图片和 PDF 交由浏览器按需解码。
3. 富文本、SVG 和 HTML 预览必须保持净化与沙箱隔离。本地资源只允许走已校验的工作区文件路由。
4. P1/P2 的新增解析器必须按需加载，不能增加默认客户端包的首屏体积；每项新增能力应记录 raw 与 gzip 包体积变化。
5. 不得轮询目录或端口状态。产物更新仅从 DSH 会话事件接收，运行 URL 状态仅在用户展开或刷新时查询。

## 8. 交付阶段

### 第一阶段：清晰的 P0 体验

保留现有 Markdown、SVG、图片和 PDF 预览；将 TXT/LOG 作为文本文档；为 CSV/TSV 增加表格阅读器；将“用户产物、源码、HTML 源文件”判定从单纯扩展名升级为路径与工具结果语义。

### 第二阶段：数据与运行成果

增加 JSON/YAML/XML/TOML 的树形阅读器、显式产物标记协议，以及运行 URL 条目。HTML 文件继续不进入 Dock，网页通过运行 URL 访问。

### 第三阶段：扩展格式

按真实使用频率增加 Office 文档只读渲染、音视频播放器和图形描述渲染。每一种格式都先以“文件信息 + 下载”兜底，渲染器稳定后再升级为默认预览。

## 9. 验收标准

1. Agent 生成报告、图片、PDF、CSV 或 Markdown 时，用户无需打开工作区即可在 Dock 阅读。
2. Agent 创建前后端项目时，`src/`、配置、依赖和 HTML/JS/CSS 源文件不会占据 Dock，也不会触发侧栏自动打开。
3. Agent 部署项目时，对话提供可点击运行 URL；后续运行 URL 条目不依赖 HTML 文件收集。
4. 用户关闭一个产物标签后，能从本会话产物目录重新打开；切换会话后看到对应会话的产物与关闭状态。
5. 未选择产物时，不产生文件内容请求；默认客户端包不会因 P1/P2 格式预览器而增长。
